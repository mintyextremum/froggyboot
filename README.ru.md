# Froggyboot

**Меню сетевой загрузки на своём сервере для компьютерных классов, лабораторий и небольших офисов.**
Любой ПК в сети загружается по PXE и видит одно меню: установщики Linux, live-системы и системы восстановления, тесты железа и **установку Windows**. Образы лежат на вашем сервере с Debian, поэтому интернет и флешки не нужны.

[English version](README.md)

```
NETBOOT 192.168.1.10   this PC: 192.168.1.57  00-1a-2b-3c-4d-5e  efi
 Safe
   [d] Boot from local disk  (default in 10 s)
   [l] Linux installers                       >
   [t] Live systems and tools                 >
 Erases disks - password required
   [!] Windows install                        >
   [!] Danger zone                            >
```

## Кому и зачем

Вы отвечаете за 1–10 классов: лаборант кафедры, школьный информатик или админ колледжа либо небольшого офиса. Windows Server и бюджета на SCCM нет, роутер настраивает кто-то другой. Зато есть старый ПК, на который можно поставить Debian.

- **Работает рядом с чужим DHCP.** dnsmasq работает в режиме proxy-DHCP: IP-адреса по-прежнему раздаёт роутер, а Froggyboot только отвечает на PXE-запросы. В сети ничего менять не нужно.
- **Windows в меню.** Публичные меню вроде netboot.xyz не могут раздавать Windows. Локальный сервер может: образы ваши и не выходят за пределы сети.
- **Безопасно по умолчанию.** Если ничего не нажать, через 10 секунд грузится локальный диск. Если сервер недоступен, тоже грузится диск. Поэтому сетевую загрузку можно навсегда поставить первой в BIOS всех ПК.
- **Всё разрушительное закрыто.** Пункты, которые стирают диск, спрятаны за дисклеймером, паролем, который проверяет сервер, и вводом слова-подтверждения.
- **Журнал.** Видно, какой ПК (MAC, IP), когда и что выбрал.
- **Без своего бэкенда.** Всё собрано из dnsmasq, nginx, Samba и текстовых `.ipxe`-файлов. Каждую строку можно прочитать и поправить.

## Требования

- Сервер с Debian 13 и статическим IP в сети класса. Подойдёт любой старый ПК. Под образы нужно примерно 30–60 ГБ.
- ПК в классе должны уметь загружаться по сети (PXE), в режиме BIOS или UEFI.
- В UEFI порядок загрузки — **сначала сеть, потом диск**. Иначе `exit` вернёт машину в меню прошивки.
- Secure Boot на ПК пока выключен: подписанная цепочка загрузки в планах.
- Заранее предупредите сисадмина сети и покажите, что это proxy-DHCP, а не второй DHCP-сервер.

## Быстрый старт

```bash
git clone https://github.com/mintyextremum/froggyboot.git
cd froggyboot
cp config.env.example config.env
nano config.env                  # SERVER_IP, IFACE, NET_CIDR, SMB_PASS, DANGER_MACS
sudo ./install.sh                # спросит пароли tech (Windows) и admin (опасная зона)
sudo ./scripts/fetch-debian.sh   # первый рабочий пункт меню, с проверкой SHA-256
```

Теперь загрузите ПК по сети: появится меню, а если ничего не нажимать, через 10 секунд загрузится диск.

`install.sh` можно запускать повторно: образы в `/srv` он не трогает, пароли сохраняет. Если сменился `SERVER_IP` или вы изменили `server/embed.ipxe`, запустите `sudo ./install.sh --rebuild-ipxe`.

Если включён фаервол (`ufw`, `nftables`), откройте для подсети класса порты UDP 67, 69, 4011 и TCP 80, 445.

## Образы

Пока образа нет, его пункт в меню просто возвращает в меню. В конце работы `install.sh` показывает список, где каждый образ отмечен как `[ok]` или `[missing]`. Куда и какие файлы класть, описано в таблице раздела [Adding images](README.md#adding-images) английского README: пути там одинаковые.

Для Windows в `/srv/images/windows/` кладутся:

- `install.wim` или `.esd` из официального ISO Microsoft;
- папка `drivers/` с драйверами Intel VMD/RST и сетевыми драйверами;
- по желанию `unattend.xml`.

Перед добавлением образа сравните его SHA-256 с официальным, допишите строку в `/srv/netboot/http/SHA256SUMS` и проверьте все образы командой `sudo ./scripts/verify-images.sh`.

## Защита

**Рубеж 1, меню iPXE**

1. Через 10 секунд грузится диск. `Esc` в главном меню тоже загружает диск.
2. Опасные пункты отмечены `[!]` и не имеют горячих клавиш, так что их не выбрать одним случайным нажатием.
3. Сначала показывается экран-предупреждение. По умолчанию выбрано «Back», через 30 секунд меню возвращается назад.
4. Логин и пароль проверяет nginx. Без них меню Windows и файлы WinPE не скачиваются.
5. Нужно ввести `ERASE` заглавными буквами.

**Рубеж 2, WinPE**

6. На экране список дисков: номер выбирается вручную, затем нужно ввести `ERASE <номер>`. Пустой ввод отменяет установку и перезагружает ПК. Разметка трогает только выбранный диск.

**Опасная зона.** Отдельный пароль `admin` и белый список MAC. Список nginx проверяет на всей папке `/danger/`, а не только на меню.

**Журнал.** Хранится в `/var/log/nginx/netboot.log` 8 недель и содержит время, IP, MAC, пользователя и запрошенный файл:

```bash
grep -E 'secure|danger' /var/log/nginx/netboot.log
```

**Честные ограничения** описаны в [SECURITY.md](SECURITY.md). Коротко: пароль идёт по обычному HTTP, а MAC-адрес можно подделать. Это защита от случайностей и любопытных, а не от злоумышленника в той же сети.
